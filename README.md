# ⚽ TaticAnalytics **Soccer match tracking data analysis engine**   
--- ## Table of Contents - [Overview](#overview) - [Motivation / Problem](#motivation--problem) - [Features](#features) - [Architecture](#architecture) - [Data Flow](#data-flow) - [Domain Model](#domain-model) - [Class Guide](#class-guide) - [API / Method Guide](#api--method-guide) - [Input JSON Format](#input-json-format) - [Usage Example](#usage-example) - [Execution](#execution) - [Algorithms and Technical Decisions](#algorithms-and-technical-decisions) - [Known Edge Cases](#known-edge-cases) - [Code Organization](#code-organization) - [Roadmap](#roadmap) --- ## Overview **TaticAnalytics** is a Java backend/core engine responsible for transforming raw tracking data (positional data) extracted from soccer match videos into analytical game metrics. The input data consists of `x, y` coordinates for players, referees, and the ball, typically generated by computer vision pipelines. The role of this module is to read this data frame by frame and reliably calculate spatial and temporal statistics such as total distance covered, maximum speed, and ball possession. The project is structured to operate currently as a console application (MVP), but its internal design strictly separates the domain, analytical logic, and I/O—making it a natural candidate to evolve into a reusable **Java library** in the future. --- ## Motivation / Problem Soccer tracking data is inherently noisy and incomplete: players overlap, the ball momentarily disappears behind players (occlusion), and detections can fluctuate between frames. Transforming this raw stream of coordinates into reliable metrics requires handling: - **Detection noise**, especially regarding the ball (occlusion, contested balls). - **Temporal attribution bias**: deciding, frame by frame, who to credit with possession time without "guessing the future" (forward-looking bias). The `AnalyticsService` exists to centralize this complexity, isolating business rules from how the data enters the system. --- ## Features ### ✅ Implemented - Deserialization of tracking JSON to the domain model. - Calculation of **total distance** covered by a player. - Calculation of **maximum speed** reached by a player (in m/s and km/h). - Calculation of **ball possession by team**, featuring protection against retroactive attribution and handling of occlusions/contested balls. - Calculation of **ball possession by player**, utilizing the same state machine. ### 📋 Planned - Full **Heatmap Data Grid**. - **`GameStatus` Filter** — handling out-of-bounds balls and half-time intervals. - **Report export** in CSV/JSON formats. - **Transformation into a `.jar` library**, with potential future integration via Spring Boot or JavaFX. --- ## Architecture The system follows a clean separation between **domain**, **analytical logic**, and **input/output**: ```text Tracking JSON ↓ TrackingDataLoader (I/O) ↓ Domain Model (FrameData, Entity, Player, Referee, Ball) ↓ AnalyticsService (business rules) ↓ PlayerStats / Ball possession Maps ``` - **`model`** — Pure domain entities (POJOs), unaware of JSON or files. - **`service`** — Business rules (kinematic calculations, possession state machine) and I/O (tracking file parsing). - **`Main`** — The entry point of the console application, orchestrating data reading and printing results. --- ## Data Flow ```mermaid flowchart TD A[tracking_sample.json] --> B[TrackingDataLoader] B --> C["List<FrameData>"] C --> D[Main] D --> E[AnalyticsService] E --> F["PlayerStats / Map<Integer, Double>"] F --> G["System.out.println (console)"] ``` --- ## Domain Model ```mermaid classDiagram class Entity { <> +int id +double x +double y } class Player { +int teamId } class Referee class Ball class FrameData { +int frameId +double timestamp +List~Entity~ entities } Entity <|-- Player Entity <|-- Referee Entity <|-- Ball FrameData "1" --> "*" Entity ``` - **`Entity`** *(abstract)* — The base contract for any physical object on the pitch: guarantees an identifier (`id`) and coordinates (`x`, `y`). - **`Player`** *(extends `Entity`)* — Represents an athlete; adds the `teamId` attribute. - **`Referee`** *(extends `Entity`)* — Represents the match referee. - **`Ball`** *(extends `Entity`)* — Represents the ball. Functions as a strong typing identifier, used via pattern matching (`instanceof Ball ball`) to differentiate the ball from players during processing. - **`FrameData`** — Represents a "snapshot" of the game at a specific time: contains a `frameId`, a `timestamp`, and a list of all `Entity` instances present in that frame. - **`PlayerStats`** — An output object encapsulating the kinematic results calculated for a player (`totalDistance`, `maxSpeed`, `maxSpeedKmh`). --- ## Class Guide ### `AnalyticsService` **Package:** `com.taticanalytics.service` The mathematical engine of the system. Calculates kinematic variables and manages the state machine responsible for ball possession attribution. ### `TrackingDataLoader` **Package:** `com.taticanalytics.service` Reads the physical tracking file and populates the in-memory domain objects. Acts as the I/O layer. ### `Entity` *(abstract)* **Package:** `com.taticanalytics.model` Base class ensuring every object on the pitch has an `id`, `x`, and `y` coordinates. ### `Player` *(extends `Entity`)* **Package:** `com.taticanalytics.model` Represents an athlete on the pitch, adding the `teamId` attribute. ### `Referee` *(extends `Entity`)* **Package:** `com.taticanalytics.model` Represents the referee on the pitch. ### `Ball` *(extends `Entity`)* **Package:** `com.taticanalytics.model` Represents the ball on the pitch. ### `FrameData` **Package:** `com.taticanalytics.model` Groups all objects on the pitch at a given time `timestamp`. ### `PlayerStats` **Package:** `com.taticanalytics.model` Data record output encapsulating kinematic statistics. ### `Main` **Package:** `com.taticanalytics` The entry point of the console application. --- ## API / Method Guide ### `calculatePlayerStats(List frames, int entityId)` - **Class:** `AnalyticsService` - **Returns:** `PlayerStats` - **Purpose:** Calculates the total distance covered and maximum speed reached by a player (specified by the `entityId` parameter). ### `calculatePossessionTimePerTeam(List frames, double radiusMeters)` - **Class:** `AnalyticsService` - **Returns:** `Map` (possession time in seconds per `teamId`). - **Purpose:** Determines how long each team maintained ball possession. Utilizes the `currentPossessorTeam` state to prevent retroactive attribution. ### `calculatePossessionTimePerPlayer(List frames, double radiusMeters)` - **Class:** `AnalyticsService` - **Returns:** `Map` (possession time in seconds per `playerId`). - **Purpose:** Granular possession tracking per individual player. ### `loadData(String filePath)` - **Class:** `TrackingDataLoader` - **Returns:** `List` - **Purpose:** Reads the tracking file and returns a list of frames converted to the domain model. --- ## Input JSON Format The input tracking JSON is parsed by `TrackingDataLoader` into the domain model. The structure maps to the `FrameData` and `Entity` objects. The exact mechanism used by the parser to differentiate a `Player`, `Referee`, and `Ball` within the JSON is handled internally by the `TrackingDataLoader` implementation. --- ## Usage Example ```java TrackingDataLoader loader = new TrackingDataLoader(); AnalyticsService analyticsService = new AnalyticsService(); List frames = loader.loadData("src/main/resources/tracking_sample.json"); // Kinematic stats for a specific player (ID 1) PlayerStats statsPlayer1 = analyticsService.calculatePlayerStats(frames, 1); System.out.printf("Total distance of Player 1: %.2f meters%n", statsPlayer1.getTotalDistance()); System.out.printf("Max speed of Player 1: %.2f m/s (%.2f km/h)%n", statsPlayer1.getMaxSpeed(), statsPlayer1.getMaxSpeedKmh()); // Ball possession by team, considering a 1.5 meter radius double radiusMeters = 1.5; Map teamPossessionMap = analyticsService.calculatePossessionTimePerTeam(frames, radiusMeters); // Ball possession by player Map possessionMap = analyticsService.calculatePossessionTimePerPlayer(frames, radiusMeters); ``` --- ## Execution The project can be compiled and run via Maven. The current entry point is the `Main` class. ```bash mvn clean compile mvn exec:java -Dexec.mainClass="com.taticanalytics.Main" ``` To run the unit test suite: ```bash mvn test ``` --- ## Algorithms and Technical Decisions ### Distance Distance is calculated as the sum of Euclidean distances between positions in adjacent frames. ### Speed Instantaneous speed is calculated as `Δ distance / Δ time`. The `maxSpeed` is updated whenever a higher instantaneous speed is detected. ### Possession State Machine (Preventing Forward-Looking Bias) Instead of crediting a time interval to whoever is closest to the ball *in the current frame*, the system uses a state variable (`currentPossessorTeam` or `currentPossessorPlayer`) to remember who **already had** possession. The elapsed time (`Δt`) is credited to this previous possessor *before* the state is updated to a new possessor. This prevents retroactively awarding time to a player who just intercepted the ball. --- ## Known Edge Cases - **Missing/Occluded Ball:** If the ball is not detected in a frame (e.g., `ball == null`), the current possessor state becomes `null` and no time is credited. - **Contested Ball:** If the minimum distance between the ball and the closest player exceeds `radiusMeters`, the frame is treated as contested (`null` possession state). --- ## Code Organization ```text src/ ├── main/ │ ├── java/ │ │ └── com/ │ │ └── taticanalytics/ │ │ ├── Main.java │ │ ├── model/ │ │ │ ├── Ball.java │ │ │ ├── Entity.java │ │ │ ├── FrameData.java │ │ │ ├── Player.java │ │ │ ├── PlayerStats.java │ │ │ └── Referee.java │ │ └── service/ │ │ ├── AnalyticsService.java │ │ └── TrackingDataLoader.java │ └── resources/ │ └── tracking_sample.json ``` --- ## Roadmap - [ ] Complete the Heatmap Data Grid implementation. - [ ] Implement `GameStatus` filter (handling ball out of bounds / half-time). - [ ] CSV/JSON report exports. - [ ] Package core as a standalone `.jar` library for future integration with Spring Boot or JavaFX.
